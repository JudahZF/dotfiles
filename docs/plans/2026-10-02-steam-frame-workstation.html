How the Steam Frame workstation works

The Frame is the hub. It holds T3 Code, terminals and windows from gale, popper and zevlor in one space. zevlor streams VR to the Frame through Valve's Steam Link. One stream carries both games and a three-screen desk. This page shows what runs where, how a session runs, and the order to build it.

primary: zevlor Valve streaming: high priority T3 Code on the Frame home LAN + Tailscale Frame managed by hand
The short version
  • T3 Code runs natively on the Frame. The arm64 AppImage pairs with the T3 Code servers on zevlor and popper over Tailscale HTTPS. One app reaches both machines.
  • Text work stays native. Konsole and VS Code connect to every host over SSH. No video, so text is as sharp as the headset can show.
  • zevlor streams VR through Steam Link. The headless Steam session runs SteamVR, with eye-tracked foveated streaming over home Wi-Fi or the Valve dongle. Games run here.
  • The big desk rides the same stream. WayVR runs as a SteamVR overlay and shows zevlor's three 1440p outputs as panels. WiVRn is the fallback if SteamVR on Linux is too unstable for long work sessions.
  • Other GUIs are windows on the Frame: popper through RDP, gale through Frame Control, and zevlor away from home through Moonlight.

How a session runs

at home · LAN

Big desk + games

  1. Put on the Frame. The keyboard and mouse reconnect.
  2. Open the KDE desktop. Frametop restores your "work" layout. T3 Code opens with zevlor and popper connected.
  3. Konsole: ssh zevlor (tmux attach), ssh popper, ssh gale.
  4. Start SteamVR on zevlor. Until Valve fixes the Linux bug, run ssh zevlor steamvr-up from Konsole.
  5. In the Frame's Steam, stream from zevlor. WayVR starts with SteamVR, and zevlor's three outputs appear as panels.
  6. Add the native panels (T3 Code, Remmina to popper, Frame Control for gale) beside them from the dashboard.
  7. To play, launch a game from zevlor's library in the same stream. WayVR panels stay available as an overlay.
  8. When you finish, quit the stream. zevlor's session keeps running, so your windows stay where they are.
away · Tailscale

Travel mode

  1. Put on the Frame. Tailscale connects to the tailnet.
  2. T3 Code reconnects to zevlor and popper over Tailscale HTTPS. No change from home.
  3. Konsole: SSH to every host, as at home.
  4. Do not use VR streaming: it is too sensitive to latency for the internet. Open Moonlight to zevlor's Sunshine for its desktop. One stream shows one output.
  5. Remmina to popper over the tailnet.
  6. gale is usually with you. Frame Control connects over the local network.
  7. Plug a power bank into the rear USB-C port for sessions longer than 1 h.

Build order

Each phase works on its own. Phase 2 comes early because Valve streaming is high priority.

Phase 0 Unblock zevlor fix ready · needs rebuild + reboot Stop the DrKonqi crash loop that filled the user manager and stopped headless RDP and Steam.
Cause (confirmed on zevlor)

drkonqi-coredump-launcher aborts with SIGABRT. Each abort is a new coredump, and each coredump starts a new launcher. The loop ran from 2026-10-01 14:49 until systemd had 131,071 user units. At that point it refused to start headless-rdp ("Argument list too long"). The user manager still had WAYLAND_DISPLAY=wayland-0 and QT_QPA_PLATFORM=wayland set, but no wayland-0 socket existed. That is the likely reason the launcher aborts after the headless compositor is gone.

Done
  • Masked the socket in nix/modules/desktop/krdp/system.nix. This applies to popper and zevlor: 
    systemd.user.units."drkonqi-coredump-launcher.socket".enable = false;
    Built zevlor's user units: the socket resolves to /dev/null. popper evaluates, and nixfmt passes.
  • systemctl --user reset-failed finished at about 12:00 on 10-02, after roughly 55 minutes at 100% CPU. After your rebuild on 10-03 the socket is masked.
Root cause: GPU hiding put the session in a user namespace

On 2026-09-24, excludeGpus added InaccessiblePaths to hide the iGPU from the headless-rdp user unit. A user manager can only build that mount namespace inside a private user namespace (uid_map 1000 1000 1), where root is not mapped. There, the root-owned /tmp/.X11-unix looks foreign, and KWin refuses to start Xwayland ("not owned by root or us"). Steam then cannot open a display, wait -n ends the session, and systemd restarts it every few seconds. The real directory was always root:root 1777. The same namespace also breaks setuid and capability wrappers inside the session.

Fix (2026-10-03)
  • Removed excludeGpus and InaccessiblePaths from krdp/system.nix. A comment there warns against mount sandboxing in this unit.
  • zevlor stubs the iGPU at boot, so the RX 9070 XT is the only GPU for KWin, VA-API, Steam, SteamVR and Sunshine: 
    boot.initrd.availableKernelModules = [ "pci_stub" ];
boot.extraModprobeConfig = ''
  options pci_stub ids=1002:13c0
  softdep amdgpu pre: pci_stub
'';
    The softdep is needed because the systemd initrd does not load modules in list order. The motherboard's video outputs stop working.
  • Built zevlor's full system. The initrd's modprobe.d/nixos.conf contains both lines, and pci-stub.ko is in the modules tree. popper evaluates.
Your steps
  1. cd ~/dotfiles && just rebuild, then reboot. The stub only takes effect at boot. Unlock LUKS over SSH from the LAN, because Tailscale is not up in the initrd: ssh -p 2222 root@Unlock LUKS over SSH: ssh -p 2222 root@zevlor.lt;zevlor LAN IPUnlock LUKS over SSH: ssh -p 2222 root@zevlor.gt;.
  2. Merge or push main when ready. It is ahead of origin/main.
Check after the reboot
  • lspci -k -s 12:00.0 shows Kernel driver in use: pci-stub.
  • ls /dev/dri shows one card and renderD128.
  • ss -ltn | grep 3389 shows krdpserver, and pgrep -a steam shows headless Steam.
  • coredumpctl list --since -1h shows no new DrKonqi dumps.
Phase 1 Frame baseline + T3 Code headset only · ~1 h T3 Code, Tailscale, SSH and native apps on the Frame. Works at home and away from day one.
Base
  1. Update SteamOS. 0.4.2 beta has streaming fixes.
  2. Turn on Developer Mode and add your SSH key (ssh steamos@frame).
  3. Install Tailscale with the frame-tailscale script. Test ssh zevlor, ssh popper and ssh gale by MagicDNS name.
  4. Install the aarch64 Flatpaks: Moonlight, Remmina, VS Code, and Firefox or Chrome.
  5. Install Frametop (distrobox) and make a "work" layout. It was tested only on SteamOS 0.3.0.
  6. Pair the Bluetooth keyboard and mouse.
T3 Code
  1. Download T3-Code-<version>-arm64.AppImage from the T3 Code releases. Use the same version as the servers (now 0.0.45-nightly.20260930.2481). Install it with Gear Lever so it appears in the app menu.
  2. On zevlor and on popper, mint a pairing link. The servers already run with --tailscale-serve: 
    t3code-server pair --tailscale --base-dir ~/.t3 --label frame
  3. On the Frame: Settings → Connections → Add environment, then paste each link. The link is valid for 5 minutes and pairs that device permanently.
  4. Optional: turn on Load balancing so new threads go to whichever machine has free CPU and memory.
  5. When the flake pin bumps T3 Code, update the AppImage too, to keep the app and servers in step.

Fallbacks, in order: app.t3.codes in the Frame's browser pointed at the tailnet HTTPS URLs, then the T3 Code Android app through Lepton. Nobody has tested the AppImage on a Frame yet, but SteamOS runs aarch64 AppImages.

Check

Do one hour of real work: T3 Code threads on zevlor, plus Konsole and tmux. Note text size, eye strain and comfort.

Phase 2 Valve streaming from zevlor high priority · repo + Steam SteamVR in zevlor's headless Steam, streamed to the Frame over Wi-Fi first, then the dongle.
A · Wi-Fi first (no kernel change)
  1. After Phase 0, confirm that headless Steam runs on zevlor (pgrep -a steam).
  2. Over RDP, install SteamVR in zevlor's Steam and opt into the SteamVR beta (2.17.8 or newer).
  3. On the Frame, open Steam → streaming. zevlor should appear, because both are on the LAN. Pair them.
  4. Test a flat game first, then a VR game.
B · Start SteamVR by hand (Valve's Linux bug)

On Linux, SteamVR does not start on its own when the Frame connects. Add a small steamvr-up command on zevlor, so you can run it from the Frame over SSH. The steam CLI passes the URL to the Steam instance that is already running in the headless session:

(pkgs.writeShellScriptBin "steamvr-up" ''
  exec steam steam://run/250820
'')

Delete it when Valve fixes the bug.

C · Valve dongle (repo change)
  • The dongle needs kernel 7.2 or newer. zevlor runs 6.18.53. Set boot.kernelPackages = pkgs.linuxPackages_latest; in zevlor/steam.nix, which gives 7.2.8 in your pin.
  • Checked: hid-tmff2 (Thrustmaster wheel), zevlor's only out-of-tree module, is already built for 7.2.8 in cache.nixos.org.
  • Plug the dongle into zevlor's USB-A. It works best in the same room as the headset. If zevlor is in another room, use a USB extension cable.
  • hardware.steam-hardware.enable is already on, so the Valve udev rules are in place.
Known NixOS issues to check
  • SteamVR asks to setcap vrcompositor-launcher for async reprojection. Inside Steam's FHS sandbox the capability does not apply. With streaming, the headset reprojects too, so try it without first.
  • SteamVR runs inside the headless KWin session. That session sees only the 9070 XT (excludeGpus) and has Xwayland, which SteamVR needs.
  • Keep SteamVR as the active OpenXR runtime. Check that ~/.config/openxr/1/active_runtime.json points at SteamVR, especially if you later add the WiVRn fallback.
Check
  • A VR game runs at 90 Hz without stutter. Compare Wi-Fi with the dongle.
  • The stream survives 30 minutes of idle desktop use.
Phase 3 zevlor: three virtual outputs repo · small Add an outputs option to services.headlessRdp and set it to 3 × 1440p on zevlor.
  • Add an outputs option (positive int, default 1). Pass it as --output-count to kwin_wayland in nix/modules/desktop/krdp/system.nix. KWin 6.6.6 includes this flag.
  • zevlor: outputs = 3; width = 2560; height = 1440;. Three 1440p panels are easier to read in the Frame than one 4K panel, and they cover about 30% more area.
  • KRDP still streams monitor 0. Games run on output 0, which Steam Link captures.
Check
  • Test by hand first: confirm that --virtual respects --output-count (kscreen-doctor -o).
  • Confirm that plasmashell keeps its panel on output 0, and that Steam Link still captures the right output.
Phase 4 Big desk: WayVR in SteamVR repo · small zevlor's three outputs as VR panels inside the Steam Link stream.
  • Add pkgs.wayvr (26.8.0) to zevlor. WayVR supports SteamVR and can register to start with it.
  • WayVR must run in the headless session, so it can see WAYLAND_DISPLAY. Starting it from SteamVR, which runs in that session, takes care of this.
  • On KDE, WayVR asks once for screen-share consent. Accept it over RDP, and check that the consent survives a restart.
Check
  • Three readable panels in the stream. Foveated streaming should make text where you look sharper than a fixed-quality stream.
  • Mixed-window test: open T3 Code and Remmina panels from the Frame dashboard during the stream. If both show together, the home flow above works as written.
Fallback WiVRn + WayVR, only if SteamVR on Linux fails

Use this only if SteamVR on Linux is too unstable for long sessions. The Frame client was merged on 2026-09-27 and is not in a release, so the server must come from nixpkgs-xr and match the client build exactly.

services.wivrn = {
  enable = true;
  openFirewall = true;
  highPriority = true;
  package = inputs.nixpkgs-xr.packages.${system}.wivrn;
  config = {
    enable = true;
    json = {
      application = [ (lib.getExe pkgs.wayvr) ];
      encoders = [ { encoder = "vaapi"; codec = "h265"; } ];  # Frame decodes 8-bit H.264/H.265 only
    };
  };
};

Do not set steam.importOXRRuntimes, so SteamVR stays the runtime for games.

Phase 5 Sunshine for away use repo · small Moonlight windows over Tailscale for zevlor's desktop.
  • zevlor: services.sunshine = { enable = true; capSysAdmin = true; openFirewall = false; settings.capture = "kwin"; }.
  • Sunshine's user service is bound to graphical-session.target, which the headless session never starts. Add a headless-session.target that headless-rdp-body starts after import-environment, and bind Sunshine to it.
  • First test Moonlight on the Frame, because hardware decode there is not confirmed. If it fails, use KRDP → Remmina.
Phase 6 gale windows small repo change + manual Mac windows as separate panels next to the Linux ones.
  • Turn on Remote Login with nix-darwin services.openssh (the module is in your pin). Frame Control and ssh gale both need it.
  • Install Frame Control on gale and on the Frame. It sends one panel per Mac window. It is a hobby project, so expect gaps.
  • Fallback: macOS Screen Sharing → Remmina VNC, with BetterDisplay virtual displays. It lags, and the Mac cursor does not show.
  • Leave out Sunshine on macOS. It always streams the main display, even when you select a virtual display (bug #4585).

Ideas

cheap

Text over pixels

Do coding in T3 Code and native terminals on the Frame. Keep video streams for apps that only have a GUI.

Native text renders at the headset's full resolution. A video stream always makes text softer, even with foveation.

medium

One headless desk, many viewers

After Phases 2–5, zevlor serves the same outputs to RDP, Steam Link, WayVR and Sunshine. You can leave RDP on gale and see the same windows in VR.

Rename headlessRdp to headlessDesk when it stops being just RDP.

small

T3 Code load balancing

With zevlor and popper both paired, T3 Code can send new threads to whichever machine has free resources.

Set zevlor to Less often while you play, so agent work does not take GPU and CPU time from a VR game.
