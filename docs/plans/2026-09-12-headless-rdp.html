Headless RDP for popper & zevlor

A persistent Plasma session that exists only while nobody is logged in at the machine, reachable over RDP, with Steam and Remote Play on zevlor. Built on KRdp — not GNOME.

2026-09-12 nixos-26.05 popper · zevlor 3 phases

What changed during planning

The original ask was GNOME RDP. Investigation ruled that out on two independent grounds, and the design that survived is simpler than the one requested.

Ruled out — GNOME

Headless "Remote Login" requires GDM, because the system daemon hands each RDP connection to a headless GDM greeter. These hosts run SDDM. Worse, that path is currently broken on this nixpkgs family: the handover daemon never starts inside the greeter and the connection aborts after ~30 s (nixpkgs#504490).

Ruled out — mirroring

niri is the daily driver on both hosts. KRdp can only mirror a KWin/Plasma session: xdg-desktop-portal-kde drags in plasma-workspace, and niri routes screencast to the GNOME portal instead. So the RDP desktop is always an isolated Plasma session, never the one on the physical monitor — which is exactly the original brief.

Net result: no GNOME, no GDM, no second desktop environment in the closure, no upstream bug, and no port conflict. KRdp already ships on both hosts via plasma6.enable (plasma6.nix); it has simply never been switched on.

Architecture

The contract in one line: local login stops everything headless; logout brings it back. One logind watcher, applied uniformly to both hosts.

Per-host split

The two hosts need different virtual-display mechanisms, for one reason: zevlor must accelerate games and popper must not.

The finding that forced this

VKMS has no render node — it is a modesetting-only driver, and PRIME buffer sharing is still listed as a TODO. A VKMS-only KWin session typically falls back to llvmpipe, which is fine for a remote desktop and fatal for gaming.

Correction to an earlier recommendation

VKMS was proposed for both hosts before Steam entered scope. It stands for popper only.

Steam & Remote Play

Can Steam run always?
No — and that is a chosen constraint, not a technical limit. The guard stops the whole session on local login, so Steam dies whenever you sit down at zevlor. In-progress downloads stop with it. What you actually get is Steam running whenever you are not at the machine. Changing this means either exempting Steam from the guard or giving it a dedicated Unix user, since Steam holds a lockfile in ~/.steam and cannot run twice for one user.
Can Steam Link work?
Yes, and it is the better transport. Remote Play streams over its own encoder path rather than through RDP's framebuffer. Use Steam Link for games and RDP for the desktop — RDP is a poor game transport.

trustedInterfaces = [ "tailscale0" ] is already set in nix/modules/nixos/network.nix:7, so tailnet access to both RDP and Remote Play is free. Only the LAN ports need opening.

Module interface

services.headlessRdp = {
  enable        = true;
  virtualOutput = "vkms" | "connector";
  connector     = "DP-1";   # zevlor: which output to force on
  steam         = true;     # zevlor: open Remote Play ports, autostart Steam
};

Disabled by default, so landing the module changes nothing until a host opts in.

Phases

01 Module and secret no behaviour change

Land services.headlessRdp disabled by default, wire it into exports.nix, and create the sops secret following the tailscale.yaml pattern — including its builtins.pathExists guard so the config still evaluates on a machine without the secret.

Resolve here: the krdpserver credentials question below. It determines the module's internal shape, so it cannot be deferred.

Done when: both hosts build, and nixos-rebuild build shows no diff in the activated system.

02 Enable on both hosts the real change

Turn the module on for popper and zevlor together. This is low risk: the KRdp path never touches SDDM, so a bad rebuild cannot cost the physical login.

Verify, in order:

  1. Virtual output appears — ls /sys/class/drm/ shows the vkms card (popper) or the forced connector as connected (zevlor).
  2. KWin is not on llvmpipe — qdbus org.kde.KWin /KWin supportInformation. Critical on zevlor.
  3. RDP connects and shows a usable Plasma desktop.
  4. Steam launches and a game runs accelerated (zevlor).
  5. Steam Link connects over LAN, then over the tailnet.
  6. Guard behaviour: log in at the physical seat, confirm the session stops; log out, confirm it returns.
03 zevlor LUKS remote unlock separate concern

zevlor's root is LUKS-encrypted (luks-e485bfac-…) with no remote unlock. After any reboot it is unreachable until someone types the passphrase at the physical keyboard — so "headless" carries an asterisk until this is done.

Add an SSH instance to the initrd with its own host keys and network setup. Deliberately last: it is an independent piece of work with its own failure modes, and it should not block proving the RDP path.

Open items

  1. krdpserver -p leaks the password via /proc/PID/cmdline. Needs checking whether krdpserver accepts a credentials file; if not, the fix is a systemd LoadCredential= plus a wrapper, not a bare CLI argument. This is the one item that shapes the module's design — resolve in phase 1.
  2. Which zevlor connector is free. Requires ls /sys/class/drm/ on the box to pick a real unused output name. DP-1 is a placeholder.
  3. Steam in a non-interactive session. Steam wants a keyring; this may need PAM unlock or a passwordless kwallet — the same class of problem KDE's forum reports for headless Plasma.
  4. H.264 encoder availability. KRdp sanity-checks for a usable encoder. popper's QuickSync should be fine; zevlor's AMD VA-API encode path is less certain.

Known sharp edges

  • If you are connected over RDP and someone logs in at the physical keyboard, your session dies immediately. That follows directly from the stop-on-login rule.
  • Steam downloads and Remote Play sessions stop every time you sit down at zevlor.
  • Remote Play over WAN Tailscale is frequently rough regardless of configuration.
  • KRdp binds 0.0.0.0:3389. Nothing else binds it today, but a future toggle of Plasma's Remote Desktop KCM inside a local session would collide silently.
